## 用业务条件选择 Agent

Agent 是 LiteFlow 节点，可以与普通组件一起使用：

```xml
<chain name="routeChain">
    THEN(prepare, IF(isOrderQuestion, orderAgent, generalAgent), saveResult);
</chain>
```

其中 `isOrderQuestion` 是返回布尔值的条件组件，两个 Agent 按[快速开始](/pages/agent-component/)注册。这里由业务规则决定调用哪个 Agent。

## WHEN 与同一会话的协调

`WHEN` 会调度多个分支，但 2.16.2 的 Harness Agent 会为共享工作区获取会话锁。同一个 `conversationId` 下，多个 Agent 不保证同时执行，即使它们的 `agentKey` 不同。

因此，将两个 Agent 放进 `WHEN` 不能直接理解为两个模型请求必然并行。需要共享会话文件、前后依赖时，优先用 `THEN` 表达顺序；需要处理独立任务时，使用不同会话发起独立流程调用。

默认 `invocation-guard.mode=AUTO` 随存储选择协调方式：JSON 只协调同一 JVM，Redis／MySQL 支持跨实例协调。不要为了让共享会话并行而在多实例环境强制使用 `LOCAL`。

## 保存分支结果

`responseData` 是 Slot 中的一份结果。多个分支写入同一个位置会互相覆盖，应在 `handleReply(reply, context)` 中写入各自的业务上下文字段。需要聚合结果时，再由后续组件读取这些字段。

## 在一个 Agent 内选择模型

如果只是按请求选模型，可通过 `routingModels()` 预先登记候选模型，再由 `routeModel(defaultModel, context)` 返回其中一个实例。声明模型与按次选择分开处理，详见[扩展点速查](/pages/agent-extensions/)。

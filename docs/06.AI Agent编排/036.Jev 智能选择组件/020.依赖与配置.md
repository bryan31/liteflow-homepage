本节适用于 **LiteFlow 2.16.2、JDK 17+**。只使用 Jev 进行语义分流时，无需配置聊天模型、会话存储或 Docker。模型与模块定位见 [Jev 模型与模块介绍](/pages/agent-jev-switch/)。

## 引入依赖

在已有 Spring Boot 项目中添加：

```xml
<properties>
    <liteflow.version>2.16.2</liteflow.version>
</properties>

<dependencies>
    <dependency>
        <groupId>com.yomahub</groupId>
        <artifactId>liteflow-spring-boot-starter</artifactId>
        <version>${liteflow.version}</version>
    </dependency>
    <dependency>
        <groupId>com.yomahub</groupId>
        <artifactId>liteflow-agent-jev</artifactId>
        <version>${liteflow.version}</version>
    </dependency>
</dependencies>
```

Spring Boot 4 将 starter 替换为 `liteflow-spring-boot4-starter`。各 LiteFlow 模块版本保持一致。

## 配置 Jev

在 `application.yml` 中选择服务入口，并配置对应平台的 API Key。默认通过 TypeSafe 调用：

```yaml
liteflow:
  rule-source: classpath:flow.el.xml
  agent:
    jev:
      provider: typesafe
      api-key: ${JEV_API_KEY}
      timeout: 3s
      min-confidence: 0.6
```

启动前设置 `JEV_API_KEY`。凭据可从 [TypeSafe 控制台](https://console.typesafe.ai/)获取。

通过 OpenRouter 调用时，将 `jev` 配置替换为：

```yaml
liteflow:
  agent:
    jev:
      provider: openrouter
      api-key: ${OPENROUTER_API_KEY}
      timeout: 3s
      min-confidence: 0.6
```

此时设置 `OPENROUTER_API_KEY`，使用 OpenRouter 的凭据。两种入口都只需引入 `liteflow-agent-jev`，组件与 EL 写法相同。

### 服务入口与默认值

| `provider` | 默认 `base-url` | 自动追加的接口路径 | 默认 `model` |
| --- | --- | --- | --- |
| `typesafe`（默认） | `https://api.typesafe.ai/v1` | `/systemone` | `jev-1.13.0` |
| `openrouter` | `https://openrouter.ai/api/alpha` | `/decisions` | `typesafe/jev-1.13` |

`base-url`、`model` 未设置或为空白时，使用所选 provider 的默认值。显式配置会保留，切换 provider 时应移除旧值或一并更新。

`base-url` 填 API 根地址，客户端自动追加上表的接口路径；不要填完整的 `/systemone` 或 `/decisions` 地址。支持末尾斜杠和网关路径。OpenRouter 入口使用 Decisions API，不能填聊天接口的 `/api/v1` 地址，也不配置到 `openai-compatible` 中。

### 配置速查

| 配置项（前缀 `liteflow.agent.jev.`） | 默认值 | 说明 |
| --- | --- | --- |
| `provider` | `typesafe` | 支持 `typesafe`、`openrouter`，决定默认地址、模型和接口路径 |
| `api-key` | 未设置 | 使用 Jev 时必填，填写所选 provider 的凭据，独立于其他模型平台配置 |
| `base-url` | 随 provider 选择，见上表 | HTTP(S) API 根地址，不可包含内嵌凭据、查询参数或片段 |
| `model` | 随 provider 选择，见上表 | 模型 ID，显式配置时覆盖对应 provider 的默认值 |
| `timeout` | `3s` | 等待完整 HTTP 响应的时限，包含响应体读取，至少 `1ms` |
| `min-confidence` | `0.6` | 自动选择目标所需的最低置信度，范围为 0～1，支持组件级覆盖 |

Spring Boot 绑定 `provider` 时会拒绝未知值；API Key、地址、超时与阈值等运行约束在执行 Jev 组件时校验。其他组件不需要提供 Jev 凭据。Java 配置使用 `JevConfig#setProvider(JevProvider.OPENROUTER)`，枚举位于 `com.yomahub.liteflow.property.agent` 包。

先按命令在哪里运行来选择：

| 需求 | 选择 |
| --- | --- |
| 只做对话或调用 Java／MCP 工具 | 沿用快速开始，不需要 Docker，也不用开启 Shell |
| 读写文件，但不执行命令 | 文件工具已提供，保持 Shell 关闭即可 |
| 在应用所在机器运行脚本或命令 | 本地模式 `GUARDED_LOCAL` |
| 在独立容器里运行脚本或命令 | Docker 模式 `DOCKER` |

本文的 Docker 模式指 **Agent 命令使用的沙箱容器**。如果只是把 Java 应用装进 Docker，仍使用本地模式，命令会在 Java 应用容器里执行。

## 分清持久存储和命令目录

| 配置 | 负责什么 |
| --- | --- |
| `session-store.*` | 保存会话状态、历史、工作区或快照 |
| `harness.local.workspace-root` | 本地命令执行时使用的工作副本 |
| `harness.docker.workspace-root` | 容器内的命令工作目录，默认 `/workspace` |
| `harness.docker.snapshot-root` | JSON＋Docker 的容器业务文件快照目录 |

文件工具与命令工具使用同一份业务文件。本地执行前从持久存储恢复到命令目录，执行后将文件变更写回；不能只备份本地执行副本。

相对路径以 Java 进程工作目录为基准。正式部署建议固定绝对路径，避免 IDE、`java -jar` 和服务管理器采用不同工作目录。

## 按运行方式继续

纯对话可以关闭 Shell，文件工具仍可使用。需要运行脚本时，按 [Shell 工具](/pages/agent-shell-tools/) 配置本地执行，或按 [Docker 沙箱](/pages/agent-docker/) 准备镜像与快照。

同一会话共享工作区。不同 Agent 协作时，约定各自的输入、输出文件名，避免覆盖其他步骤的产物。

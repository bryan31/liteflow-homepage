## 给 Agent 提供文件

Agent 默认可以调用 `read_file`、`write_file`、`edit_file`、`list_files`、`grep_files`、`glob_files`。在提示词中使用 `input/orders.json`、`output/report.md` 这类工作区相对路径即可。

JSON 本地模式中，业务文件默认位于：

```text
<json-root>/workspace/<应用名>/<会话ID>/
```

JSON＋Docker 模式中，可把共用的 `AGENTS.md`、`knowledge/` 等资料放入 `json-workspace-root`，默认会复制到容器工作区；未配置时使用 `<json-root>/workspace`。这是静态资料复制，容器修改不会自动回写源文件。Redis／MySQL 模式通过配置的 Skills 仓库、文件接口或业务工具提供输入，不把本地目录当作持久文件存储。

生成文件后，下载接口和附件展示由应用提供；容器路径本身不能直接作为浏览器下载地址。

## 文件路径

向模型描述任务时，使用工作区相对路径，例如“读取 `input/orders.json`，将结果写入 `output/report.md`”。本地和 Docker 模式都沿用这种写法，无需把宿主机绝对路径写进提示词。

Skills 资源准备到 `.skills-cache/`，生成报告等业务文件应写到其他目录，避免后续技能刷新覆盖。

## 将产物交付给用户

文件工具创建文件后，应用仍需提供下载接口。需要让 Agent 主动交付附件时，通过 `customizeHarness(builder)` 配置应用实现的 `ArtifactDeliveryTarget`，启用 `deliver_artifact`。

附件的保存、下载鉴权和展示由应用实现，不能把容器内路径直接作为浏览器下载地址。[演示项目](/pages/agent-example/)提供了聊天附件下载、历史记录及重启后恢复的完整实现，可作为接入参考。

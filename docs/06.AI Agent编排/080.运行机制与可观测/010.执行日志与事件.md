## 执行日志

内置日志默认开启，记录 Agent、推理、工具执行和模型调用等阶段的进入、完成及错误信息。关闭时配置：

```properties
liteflow.agent.execution-log-enabled=false
```

排查时结合会话、节点和请求标识定位一次调用，并从 `response.getCause()` 获取失败原因。日志开关不代替流式事件监听器，也不控制聊天历史是否保存。

## 面向界面的执行事件

快速开始已展示 `agent.text.delta` 的监听方式。同一个监听器还可以根据事件类型显示执行状态：

| 事件 | 常见用途 |
| --- | --- |
| `agent.text.delta` | 正文增量，读取 `event.getText()` |
| `agent.tool.call.start`／`agent.tool.call.end` | 工具调用开始／参数接收结束 |
| `agent.tool.result.end` | 工具结果完成 |
| `agent.confirm.required`／`agent.confirm.result` | 人工确认请求／结果 |
| `agent.result` | 当前 Agent 的结果 |
| `agent.error` | 执行错误 |

多 Agent 流程可通过事件的节点和请求标识区分来源。`agent.result` 不代表整条链结束，最终仍应检查 `response.isSuccess()`。监听器异常默认会中断调用；允许展示事件丢失时，才设置 `event.listener-failure-mode=LOG_AND_CONTINUE`。

## 事件失败策略

监听器是调用链的一部分，默认 `FAIL_FAST`。SSE 或 WebSocket 发送失败时，如果应用允许展示事件丢失，可配置：

```properties
liteflow.agent.event.listener-failure-mode=LOG_AND_CONTINUE
```

该设置只改变事件监听器异常的处理，不会忽略模型、工具或存储失败。最终流程状态仍由 `LiteflowResponse` 判断。
